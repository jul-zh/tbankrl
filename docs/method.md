## Две разные цели рекомендации

Предсказание следующего объекта отвечает на вопрос: «С чем пользователь
вероятнее всего взаимодействует после истории $h$?» Обозначим распределение
модели как $\pi_\theta(a\mid h)$. Обучение по журналу минимизирует
кросс-энтропию (CE) $-\log\pi_\theta(y\mid h)$ для наблюдаемого следующего объекта $y$.

Вероятность взаимодействия и качество опыта не тождественны. В этом исследовании
добавочная цель - доля просмотра. Поскольку для большинства возможных рекомендаций
отклик не наблюдался, используется обученная модель награды $\hat r(h,a)$.
Следовательно, RL оптимизирует **ее прогноз**, а качество этого прогноза
становится отдельным ограничением исследования.

## Исходная модель: GPT-2 для ID объектов

Каждый объект - отдельный токен. GPT-2 обучается с нуля, без текстовых весов:
два слоя, скрытая размерность 128, четыре головы внимания, контекст 32 позиции,
около 1,84 млн параметров. Матрица входных представлений используется также
на выходе. По последней непустой позиции предсказывается один реальный следующий
объект. Причинная маска запрещает внимание к будущим позициям, а маска заполнения
исключает искусственно добавленные пустые позиции.

Такое представление удобно для генерации: выбранный ID можно добавить в историю
и повторить предсказание. Однако добавленная рекомендация еще не является
просмотром пользователя. Это различие принципиально для нескольких шагов вперед.

## Модель награды

Целевая величина - $r=\operatorname{clip}(\texttt{watched\_pct}/100,0,1)$.
Модель усредняет представления объектов истории и объединяет результат
с представлением кандидата, их поэлементным произведением и абсолютной разностью.
Небольшая полносвязная сеть с сигмоидой предсказывает число от 0 до 1;
обучение минимизирует среднеквадратичную ошибку.

Модель видит историю и кандидата, но не отклик целевого объекта.
Пропуски награды исключаются из ошибки; ненаблюдавшимся действиям не назначается
нулевой отклик. Специальный токен неизвестного объекта участвует в среднем
истории: при большом количестве таких позиций информативность истории снижается.
Все варианты RL используют одну замороженную модель награды.

## Почему REINFORCE

Действие - дискретный ID, поэтому обычное дифференцирование через выбор объекта
не подходит. REINFORCE оценивает градиент ожидаемой награды через
$\nabla_\theta\log\pi_\theta(a\mid h)$ для действий текущей модели.
При горизонте в один шаг это оптимизация ожидаемого отклика в фиксированном
контексте, без модели переходов пользовательского состояния.

Основная цель с ограничениями:

$$
J(\theta)=\mathbb E_{h,a\sim\pi_\theta}[\hat r(h,a)]
-\beta D_{KL}(\pi_\theta\Vert\pi_0)
-\alpha L_{\mathrm{next}}(\theta).
$$

Здесь $\pi_0$ - исходная GPT-2, а $L_{\mathrm{next}}$ - ошибка предсказания
реального следующего объекта из обучающей части. Расхождение Кульбака - Лейблера
удерживает распределение вблизи исходного; дополнительное предсказание
непосредственно сохраняет связь с наблюдаемым поведением.
KL и ошибка следующего объекта здесь усредняются по пакетам реальных контекстов.

В реализации функция потерь для одного шага имеет вид

$$
L=-\log\pi_\theta(a\mid h)\,
\operatorname{stopgrad}[\hat r(h,a)-\beta D_{KL}(h)-b]
+\beta D_{KL}(h)+\alpha L_{\mathrm{next}}.
$$

Экспоненциальное среднее прошлых возвратов $b$ снижает дисперсию оценки градиента.
При одном шаге KL зависит от контекста, поэтому его отсоединенная часть внутри
квадратных скобок не добавляет ожидаемого градиента по действию; прямой градиент
KL учитывается отдельно. KL считается точно по реальному каталогу.
Во время выбора действия и вычисления его вероятности случайное зануление
активаций отключено; градиенты рекомендующей модели сохраняются.

Для пяти шагов используются дисконтированные возвраты с $\gamma=0{,}95$,
включающие будущие награды и KL-затраты. Сгенерированные ID последовательно
добавляются в контекст. Это исследование поведения генератора, а не симуляция
реальных решений пользователя.

## Какие ограничения проверялись

- **Вес KL:** насколько далеко модель может уйти от исходного распределения.
- **Штраф известного объекта:** $\hat r(h,a)-0{,}2\,\mathbb 1[a\in h]$ как другой
  вариант награды, снижающий стимул повторно предлагать знакомое.
- **Ошибка следующего объекта:** веса $\alpha=0/0{,}1/0{,}3/1{,}0$ для
  сохранения релевантности.
- **Усреднение по другим траекториям:** четыре цепочки на контекст и средний
  возврат остальных трех как опорное значение. Это вариант REINFORCE,
  без ограничения отношения вероятностей и повторного использования пакетов.
- **Горизонт:** один или пять сгенерированных объектов.

Простое сравнение без изменения весов - переранжирование ста кандидатов GPT-2
по $\log\pi_0(a\mid h)+\lambda\hat r(h,a)$. Оно показывает, нужен ли RL
для наблюдаемого компромисса или достаточно использовать награду при выдаче.

## Связь с близкими работами

[Petrov и Macdonald, 2024](https://arxiv.org/abs/2403.04875) рассматривают
последовательную генерацию рекомендаций и RL для согласования GPTRec с целями
помимо точности. Здесь используется близкая идея дополнительной цели, но исходная
модель обучается непосредственно на следующих ID; схема обучения учитель - ученик
из GPTRec не воспроизводится.

[Matveev и соавторы, 2026](https://arxiv.org/abs/2607.02818) исследуют
сессионную оптимизацию REINFORCE по ранее собранным данным с многошаговой
коррекцией и моделью пользовательского отклика. В нашей постановке такой
симулятор реакции и коррекция по вероятностям показов не используются.
Поэтому пятишаговую диагностику нельзя интерпретировать как оценку удержания.
