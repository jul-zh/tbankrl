# Воспроизведение

[Обзор](../README.md) · [Протокол](protocol.md) · [Результаты](experiments.md)

Есть три уровня воспроизведения: проверить опубликованные числа, повторить
оценку сохраненных весов или заново обучить модели. Для чтения и проверки
выводов достаточно первого; он не требует датасета и GPU.

## 1. Проверить числа и рисунки

Рекомендуется отдельное окружение Python 3.11 или новее:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
python scripts/verify_results.py
python scripts/build_figures.py
python -m pytest -q -ra
```

Проверка результатов сверяет:

- контрольные суммы 34 обезличенных массивов и исходных модулей;
- Recall и NDCG по сохраненному рангу правильного объекта;
- средние прогнозы награды и опубликованную таблицу отдельных состояний;
- 84 парных бутстрэп-интервала итоговой оценки;
- наличие трех основных случайных запусков и соответствие весам из фиксации.

Порядок строк внутри каждой части одинаков для всех методов. Исходные ID,
контексты и реальные отклики в массивы не включены. Это проверка численного
анализа результатов, а не повторное применение нейросетей.
Описание формата — в [results/README.md](../results/README.md).

Без PyTorch нейронные группы тестов явно пропускаются. Для их выполнения:

```bash
python -m pip install -e '.[train,test]'
python -m pytest -q -ra
```

Они используют небольшие искусственные примеры, проверяют маски,
направление градиентов, заморозку исходной модели и модели награды,
сдвиг целей и восстановление. Длительное локальное обучение не требуется.

## 2. Подготовить Colab

```bash
python scripts/make_colab_bundle.py
```

Будет создан `dist/colab_bundle.zip` с исходниками, конфигурациями, тестами
и ноутбуками. Датасет, численные результаты и веса в него не входят.
Откройте нужный ноутбук в Google Colab, включите GPU и загрузите архив
в первой ячейке. Код обучения находится в `src/recsys`, ячейки только
устанавливают окружение и вызывают модули.

Итоговая оценка исследования выполнена на Tesla T4, Python 3.13.16,
PyTorch 2.11.0+cu130, Transformers 4.46.3.
[Зафиксированное окружение](../results/metadata/environment.json).
В ноутбуках версии PyTorch и Transformers ограничены файлом
`constraints_colab.txt`; остальные зависимости заданы в `pyproject.toml`.
При другом окружении сначала должны пройти тесты и небольшой запуск.

## 3. Повторить итоговую оценку сохраненных весов

Используйте [02_evaluate.ipynb](../notebooks/02_evaluate.ipynb).
Нужны подготовленные данные и веса, соответствующие
[configs/final_selection.json](../configs/final_selection.json).
В конфигурации перечислены именно 14 состояний рекомендующей модели из опубликованной
оценки, их шаги и контрольные суммы; вместе с тремя коэффициентами
переранжирования и популярностью получаются 18 вариантов.

По умолчанию входная папка — `MyDrive/tbank_rl_recsys`:

```text
prepared/                       исходная когорта для модели награды
artifacts/rm/best.pt             замороженная модель награды
scaling_v1/data/large/           расширенное обучение и фиксированные отложенные данные
scaling_v1/large_128/best.pt      исходная рекомендующая модель
rl_preserve_v1/branches/         состояния RL
rl_ablation_v1/branches/         отдельный контроль CE+KL
```

Эти входы остаются за пределами Git. Пути можно изменить в ноутбуке.
Результаты записываются в отдельную папку `evaluation_reproduction`;
исходные состояния не перезаписываются.

Этапы: проверка файлов → проверка контрольных сумм и происхождения →
замер на 128 проверочных примерах → оценка фиксированных состояний → экспорт.
Обучение и выбор по тесту в этом ноутбуке отсутствуют. После каждой модели
результат сохраняется в Drive; повторный запуск использует завершенные оценки.
Успешное завершение подтверждают `primary_complete` и `available_models_complete`
в `progress.json`, а также архив `results_final_test_v1.zip`.

## 4. Обучить модели с нуля

Используйте [01_train.ipynb](../notebooks/01_train.ipynb). По умолчанию
выбрана отдельная папка `MyDrive/rl_recsys_reproduction`, чтобы новые результаты
не смешивались с опубликованными. Все этапы запускаются отдельными ячейками.

1. **Данные.** Загрузчик получает закрепленную версию KION, проверяет
   5 476 251 строку и сохраняет контрольную сумму CSV. Подготовка закрепляет
   даты 21 июля и 6 августа 2021 года. Расширение обучения сохраняет словарь,
   проверочные и тестовые примеры исходной когорты.
2. **Небольшие запуски.** 12 обновлений модели награды и по 50 обновлений
   вариантов GPT-2. Измеряются скорость, память и стоимость проверки;
   эти веса не подставляются в основные эксперименты.
3. **Модель награды.** Обучение на исходной когорте, выбор по проверочной
   среднеквадратичной ошибке.
4. **GPT-2.** Сравнение исходного и расширенного обучения при размерности 128,
   затем размерности 256; сохранение лучшего проверочного NDCG.
5. **RL.** В ячейке `STUDY` по очереди выберите `mods`, `preserve`, `ablation`:
   семь модификаций; четыре веса дополнительного предсказания по трем запускам;
   контроль без REINFORCE. Для каждой серии сначала выполняется небольшой запуск.
6. **Фиксация.** После `preserve` и `ablation` скрипт `freeze_run.py` фиксирует
   состояния нового обучения до оценки теста. Основные `best.pt` уже выбраны
   по проверке; для фиксированных сравнений требуется именно шаг 2500.
7. **Тест.** В `02_evaluate.ipynb` укажите новую папку `BASE` и созданный
   `fresh_selection.json`. Итоговые числа сохраняются отдельно.

`bind_run.py` переносит рабочие гиперпараметры конфигурации и закрепляет
контрольные суммы **входов нового запуска**. Он не требует совпадения новых
весов с весами опубликованного исследования. Повторное обучение может дать
другие значения из-за случайности и версий вычислительных библиотек;
проверять следует протокол и полученные измерения, не подгоняя их по тесту.

## Бюджет и восстановление

| Этап | Ограничение |
| --- | --- |
| Модель награды | 6000 обновлений или 35 минут |
| Каждая основная GPT-2 | 12 условных проходов, ранняя остановка или 45 минут |
| Каждая ветка модификаций RL | 2000 обновлений или 12 минут |
| Каждая ветка весов предсказания и контроля | 2500 обновлений или 12 минут |
| Итоговая оценка | 60 минут суммарно; до 5 минут на модель |

Это верхние пределы, а не прогноз длительности. Для выполненных серий основные
RL-запуски с внутренней проверкой и сохранением заняли 14,64 / 43,70 / 21,66
минуты соответственно; установка, подготовка и итоговая оценка сюда не входят.

Сначала измеряется небольшой запуск; полное обучение рассчитано на отдельные
сессии Colab. Оптимизатор, генераторы случайных чисел и положение выборки
сохраняются вместе с весами. Исходный модуль обучения продолжает `last.pt`
через `--resume`; в сериях сравнения восстановление автоматическое.
Временные границы серий хранятся в журнале и не сбрасываются переподключением.
Новый эксперимент получает отдельную папку; тест не используется для
решения о продолжении или изменении настроек.
